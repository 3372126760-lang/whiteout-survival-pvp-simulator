## 属性转换

统一队列边界 `queueConversionSide` 构造正常 Single 输入，复用已有单撞的来源反推、英雄静态差值、专武静态差值及专武外部 Buff 同组处理。Criterion、MatrixCriterion、Theory、正式场景均经过此边界。

历史特殊加成采用既有 canonical 公式：

\[
R_{raw}=(100+R_{report})\frac{1+D}{1+B}-100-A
\]

其中 A 是官职百分比点，B/D 是同组 Buff/Debuff 小数之和。历史页面上的加成视为已经生效，不用当前挑战 / 驻防 / 集结条件重新过滤。

反推后保留历史英雄和专武基准，再由现有单撞计算预期与历史静态贡献差，叠加当前侧级宠物/专家及预期专武场景增益。每个子战斗只引用一次共享环境，不把三队 Buff 累加到同一场。

`reportLineage.attributeSnapshot` 与当前存储属性绑定；`historicalLineageConfirmed` 标记导入、历史编辑或优化基准捕获的明确来源。旧的未确认无英雄残留仍会清理；明确历史来源允许“历史有英雄 → 预期 EMPTY_HEAD”。改变预期英雄不重绑历史英雄，修改历史值重新反推对应来源。

未绑定的旧来源还需验证其能否描述当前属性。例如低属性面板残留整套 S11 来源、反扣后因子不为正，不会在编辑时被提升为明确历史来源；已确认的历史来源保留并报告真实无效输入。单撞 / 集结的最终战报模式仍直接使用最终属性，预测模式才执行历史反推。

比例变化不改变属性。英雄或专武变化立即影响预期属性、Criterion/Theory 模板和正式初始属性。没有回填默认英雄来修复 lineage。

## OCR

本地整图识别属性和特殊加成，保留框、置信度、原文和 registry 结果。兵种等级、FC、图标推断保持关闭，兵种配置不由 OCR 改写。

预览分为属性识别和特殊加成识别；支持左右历史列、修改名称 / 数值 / 类型 / 属性 / 目标 / 兵种范围，冲突选值、确认、删除、手动补充。完整性三态：尚未完整、完整核对、明确为零。

历史对方对本方施加的减益只从本次识图上下文读取，不混用正式另一侧配置。低置信度、未知或冲突项禁止提交。待确认项目的预览总计只阻塞相关 stat，实际应用需十二项及必要特殊上下文全部确认，之后原子更新所选队列。

紧凑地心 Schema 仍约束历史战报字段（锻炉我方9项、敌方2项等）；特殊加成可能使反推原始十二项不再成对，所以原始空间逐项反推，不再次强制配对。历史上下文跟数值快照绑定并保存在专用模式配置中。

## 六排列搜索

敌方枚举 012、021、102、120、201、210，始终调用现有固定 cursor 调度器，仅改变初始完整队列顺序。

| 设置 | 评价域 | 排序 |
| --- | --- | --- |
| fixedCurrent | 当前敌方顺序 | 当前胜率 |
| allPermutations（默认） | 六种顺序 | 最差 → 平均 → 当前胜率 |
| worstCase | 六种顺序 | 最差 → 平均 → 当前胜率 |

我方默认允许整队六种位置，勾选固定我方顺序则只改变各源队英雄 / 比例。英雄 / 比例锁跟随来源队，不随换位绑定到错误位置。

C0 保留逐队对三个敌方来源的覆盖；有界 Pair / Triple 后，C1 Criterion 和 C2 Theory 都按完整敌方排列评价。Triple 上限包含我方位置展开，避免无意翻六倍候选数量。正式数值层依次比较最差、平均、当前三个指标，不使用 avg/worst 加权混合。

正式首轮每个敌方顺序默认 10 条共同 trajectory；中期给当前、最差和接近最差的顺序补样本，当前方案覆盖全部顺序用于配对比较；Final 完整覆盖六排列、每排列默认累计1000场。候选和 baseline 都复用同一排列的 seed 前缀，Worker / 同步入口共享该流程。

结果中 `trials` 是全部排列样本总数；带 `permutationAudit` 的 `winRate` 是最差排列胜率，不能用合计 `wins/trials` 替代。各排列各自使用包括失败 Trial 的分母。平均是六个排列胜率的等权平均。

建议我方顺序、当前/平均/最差胜率、最危险/最佳敌方順序及各排列样本数都显式显示。最终卡片附每队历史 / 推荐英雄、十二项属性变化和转换审计。

搜索候选的来源索引保持有序；正式 evaluation key 包含历史快照、预期英雄 / 专武、转换后属性、比例、位置、两侧共享上下文、兵种与完整敌方队列顺序。引擎模板缓存仍使用完整输入签名，不做无序队列排序去重。
