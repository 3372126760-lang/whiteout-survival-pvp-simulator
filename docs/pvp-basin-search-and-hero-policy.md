# 英雄过滤与多盆地比例精搜交付报告

日期：2026-10-06。供后续 AI 分析当前实现和验收证据。

## 1. 本轮范围

保留 TheoryPreFilter → Monte Carlo 架构、TheoryScore 的 35% 静态优势／65% 浮点回合优势，以及最终由正式 ScenarioRunner／BattleEngine 决定胜率的流程。

新增自动英雄候选规则、由正式技能结构派生的保守支配审计、多个盆地的连续 5% 扩张，以及多个优秀区域的局部 1% 搜索。单撞和集结单波共享盆地模块；333 保持固定比例；三队列只接入自动英雄规则，原坐标下降与调度不变。多波继续复用原 Beam 流程。

核心保护：本轮开始前记录的 battle、damage、formulas、round、heroSkills、troopSkills 共 **55 个文件**，结束核对均未变化。没有修改 BattleEngine、DamageEngine、HP、正式技能规则、ServerStage 目录或手动英雄数据库。证据：[核心哈希核对](../examples/optimizer-core-hash-verification.json)、[原始哈希](../examples/optimizer-core-hashes-before.json)。当前目录没有 Git，这份哈希是本轮变更边界证据，不是 Git 历史审计。

## 2. 自动英雄过滤与实际搜索空间

### 规则

- S1／S2 允许 R、SR；S3 及以后自动搜索排除 R、SR。
- 每套三车头至少一人属于正式 metadata 中的近三代；S1 有效集合为 `{1}`，S2 为 `{1,2}`，S11 为 `{9,10,11}`。
- generation 未记录或 null 不根据名称／ID 推断，不能独立满足近三代条件；有其他近三代英雄时可参与其余位置。
- 稀有度规则同时用于新搜索的车身英雄；用户明确固定的车身槽仍按手动配置保留。近三代三人规则只检查车头。
- 原始当前配置始终作为精确 baseline 单独正式复验，不被自动英雄规则删除。显式 `protectedCandidates` 仍须符合自动车头池及固定车身约束；不符合搜索规则的手动方案可继续直接模拟，但不能作为自动候选保护项。

## 3. 严格支配证明边界

`HeroEffectSignature` 由正式英雄远征数据、完整战斗技能定义、实际技能等级与专武技能档位派生，没有手写“新代替代旧代”关系表。

签名保留 effect kind、数值、概率、group、recipient、troop／target scope、operation、触发、时序、持续、上下文、位置等语义；静态属性、完整专武配置与专武等级作为比较条件。未实现完整技能覆盖、规则未确认、复杂行为／计数／生命周期／目标限制等都会阻止严格证明。

第一版只允许非常保守的证明：完整对应的确定性、持续被动、正向且单调的 effect，同样的语义和静态／专武条件，所有数值不弱且至少一个严格更强。概率、静态或专武条件尚不能证明相同的数值优势最多为 likelyDominated。替代还必须保留近三代组合合法性，否则不删除。生效更早、持续更长等宽松包含关系本轮没有擅自推断。

| 分类 | 当前 S11 实际结果 | 行为 |
| --- | ---: | --- |
| strictlyDominated | 0 | 没有实际删除英雄；实际证明关系列表为空 |
| likelyDominated | 0 | 没有实际关系；若以后出现，仍保留进入理论层 |
| nonDominated | 34 | 无完整上位证据或存在复杂机制，正常参与 |

因此本轮没有任何需要列举的真实 strict dominance 证明，也没有仅因代数／单个技能相同而删除英雄。测试中的人工签名用于验证证明边界，不是给正式英雄制造支配关系。

高级调试输出 `heroPoolAudit`：原始池、稀有度排除、近三代集合、支配关系／逐 effect 比较、三档分类、过滤后池与分层数量。`exclusionReason` 分别为 `rarityRule`、`recentGenerationRule`、`strictDominance`。

## 4. 多盆地正式比例搜索

```text
合法性与英雄过滤
 → 每套车头完整 231 点 5% 理论网格
 → 多个局部峰 + uncertainty / diversity / seeded exploration
 → M1 5 场：全部代表实际进入正式引擎
 → M2 20 场
 → 多个优秀盆地：50 场共同种子、六邻居 5% 连续爬坡
 → 多个中心各生成局部 1% 窗口
 → 20 / 50 / 200 场正式筛选
 → Top 与受保护参照 1000 场 + 精确当前 baseline
 → 正式胜率排序
```

默认 `basinSearch` 参数：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| maxBasins | 4 | 同时起步的盆地上限 |
| maxBasinsPerHead | 2 | 同车头／车身最多两个相隔较远的起点 |
| maxClimbRounds | 6 | 每个盆地最多扩张轮数 |
| fineBasins | 4 | 进入 1% 搜索的盆地上限 |
| fineRadius | 5 | 盾、矛各在中心 ±5 百分点的窗口 |
| separation | 10 | 同车头起点的最大分量距离至少 10 百分点 |

每次从一种兵转移 5 百分点给另一种兵，共六个内部邻居。中心和邻居使用完全相同的场数和 seed offset，发现更优邻居就移动并继续；停止原因记录为 localOptimum 或 roundBudget。边界点只生成合法邻居。

局部 1% 窗口固定车头／车身，盾和矛逐个整数百分点枚举，射手补足 100%。内部窗口最多 121 点；重复候选按完整 key 去重。不执行所有英雄组合 × 5151 的全局 1% 搜索。默认允许多个不同盆地同时精搜，同一车头相隔较远的盆地也可保留。

相同候选、场数、seed offset 的完整正式结果可以复用；残缺／提前淘汰样本不缓存为完整结果，不进入下一阶段。爬坡中心已完成 50 场，保留进入 M3，避免被局部窗口的 20 场噪声提前挤出。阶段胜率优先，剩余兵数作为次序；Final 不提前淘汰。TheoryScore 不变成胜率，也不能直接决定最终排名。

`ratioSearchAudit` 包含每个盆地种子、逐轮中心、轮数、停止原因、精搜中心、窗口候选数，及去重后的新粗邻居／新细比例／精搜车头和盆地数量。新参数通过配置 codec 自动保存、JSON 导入导出和旧配置默认值恢复。页面高级调试按需输出，不预先渲染大块 JSON。

## 5. 下一轮输出与期望传播

私有理论程序从正式技能 metadata 派生状态，复用正式伤害、HP、属性和 effect 聚合函数，保持正式行动顺序、回合开始人数快照和回合末统一扣血。理论兵数使用浮点数，不做正式伤亡整数取整，不调用 BattleEngine 或 RNG。

对来源兵种 s、目标兵种 t：

```text
O(s→t) = sqrt(N0) × sqrt(n_s,float)
         × 正式兵种常数／系数／属性／克制／伤害修正
         × 当前可行动概率与对应伤害段依赖
```

内部为每侧保留 3×3 目标输出矩阵。`O0` 是初始下一轮期望输出，`Or` 是估计结束状态若再进入下一轮的输出，`R_output=Or/O0`。同目标、同状态下 25% 剩余人数对应约 50% 输出；不会使用“人数×攻击”替代正式公式。这些字段作为解释与辅助诊断，当前仍保持 TheoryScore 的原始 35%/65% 权重。

标量按当前实际存活目标和改目标概率汇总；矩阵保留目标差异。奇袭分别计算通常目标与射手优先目标的伤害，例如盾与射都在时 `0.8Dshield+0.2Dmarksman`。当前正式默认优先顺序为盾→矛→射，奇袭为射→盾→矛；没有因需求中的示例另改正式索敌规则。标量扣除期望护盾吸收，矩阵记录各目标潜在输出；无存活目标时标量为零，不代表部队在假设新敌军面前的能力。

支持与测试内容：

- 数值概率按 `p×value`，`calibratedEquivalent` 优先；25% 普攻双倍暴击为 1.25 倍期望。
- 目标重定向分支分别计算和分配，不平均成统一目标倍率。
- 普攻、独立 extraDamage、同主攻击段的附加伤害分别处理；mainAttackAttempt 与 successfulHit 等语义派生命中依赖，闪避不会粗暴削减所有技能伤害。
- 眩晕使用可行动概率边际；周期维护每兵种实际主攻击计数，按第 N 次触发，不平均到每回合。自然回合周期、nextRound 生效和持续／刷新按私有时序状态执行。
- 多目标独立附伤、Buff/Debuff、叠层、联动概率，以及加托护盾期望预算；护盾在伤害转 HP 损失前吸收，当前层与次回合待生效层分开保存。
- 按活跃 effects 缓存伤害系数，按回合／存活目标／计数／效果／控制状态缓存可复用行动计划，按实际 `sqrt(n)` 缩放。单位人数构建计划避免比例扫描顺序影响浮点结果；护盾等人数相关非线性情况绕过行动计划复用。

### 理论边界与待校准项

理论层仍是筛选估计，不是完整概率状态树。目标绑定标记、一次性标记易伤、衰减伤害和 skipMainAttack 暂未完整传播；这些效果在 `omittedMechanisms` 中标记并提高不确定性。多回合随机刷新、眩晕与攻击计数的联合分布、随机目标关联以及随机护盾的 `E[min]` 使用近似，非线性属性分母也不等于完整分支积分。周期无眩晕时按整数计数执行，有概率控制时的计数分布尚未展开为完整联合树。

没有伪造真实战报校准值，也不把这些近似称为已验证游戏规则。多峰／探索／参照保护仍用于降低理论遗漏风险，正式高场次复验仍决定最终推荐。没有严格全局最优保证。
